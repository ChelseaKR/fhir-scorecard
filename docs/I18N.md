# i18n status: N/A

fhir-scorecard does not implement internationalization.

**Reason:** the graded subject matter and the audience are English-bound by the domain itself:

1. **The findings quote normative spec text.** Every finding cites the FHIR R4 or SMART App
   Launch specification, which is published in English. Translating findings would put
   translated prose next to untranslated normative citations and weaken the "tied to cited
   spec text" property the project depends on.
2. **Specialist audience, not a public-service workflow.** The site serves health-IT
   implementers, policy analysts, and researchers evaluating US regulatory API surfaces
   (CMS interoperability rules). It is not a civic service that gates access to benefits,
   transit, or legal processes for the general public.
3. **The dataset is language-neutral.** `dataset.csv`, the JSON API, and the MCP server expose
   codes, grades, URLs, and timestamps; the human-language layer is the finding text covered
   by (1).

**Scope note:** dates and numbers in the published dataset use ISO 8601 and locale-neutral
formats already.

**Revisit if:** the project adds a consumer-facing explanation layer (for example,
plain-language guidance for patients choosing a payer), or a non-US registry whose regulatory
context is not English-first. Either would create a genuine end-user translation obligation.
